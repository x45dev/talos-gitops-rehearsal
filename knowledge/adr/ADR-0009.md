# ADR-0009 - Adopt the RKA ADR-0013 spec-lifecycle gate early, ahead of the rka-template release train

Records a deliberate, maintainer-directed exception to this repository's standing
release-train rule, and what was done under it.
Decided by the human maintainer on 2026-07-24; the agent implemented and scribed it.

## Context

RKA ADR-0013 governs feature specifications as governed bundles under
`knowledge/specs/<NNN>-<slug>/`, enforced by three validator rules: rule 8 (an archived
document must carry an `Extraction record` section), rule 9a (a bundle's documents share
one status, because a bundle has one lifecycle), and rule 9b (a bundle whose `tasks.md`
is fully checked must be `archived`).
Rule 9b is the load-bearing one: it turns "shipped but never retired" into a commit-time
failure rather than a slow rot.

This repository consumes upstream conventions at tagged releases only, never at upstream
HEAD (RKA ADR-0012, recorded in `knowledge/context.md` "System patterns").
The 2026-07-22 upstream survey found these rules present only in the RKA reference
repository's `main`; `rka-template` v0.4.0, the pin this repo tracks, ships a validator
that stops at rule 7.
The survey therefore deferred adoption and recorded the wait in `knowledge/activeContext.md`
and `knowledge/progress.md`.

Two facts made the deferral uncomfortable rather than merely patient.
First, this repository is the motivating example the upstream rules were written against:
its `001-governance-parity` bundle was 18 of 18 tasks complete while still `status: draft`,
which is exactly the failure rule 9b catches.
Second, the deferral was load-bearing in the wrong direction: it was cited to justify
leaving a finished bundle un-retired, conflating the governed migration (genuinely gated on
the release) with plain archival (never gated at all).
That conflation was corrected on 2026-07-24 by archiving the bundle in place.

The maintainer then directed adoption of ADR-0013 now, rather than waiting for the release
train.

## Decision

Adopt the ADR-0013 spec-lifecycle gate early, as a recorded exception to ADR-0012's
tags-only rule:

1. **Port rules 8, 9a, and 9b** into `scripts/validate-frontmatter.sh`, together with
   spec-bundle awareness in rule 4 (a bundle document's filename carries its role and its
   id is `<role>-<NNN>-<slug>`), from the RKA reference repository at commit
   `ce4a12e4a8ee158232952b2dff66687fda4756a4`.
   The port keeps this repository's existing local adaptations: the awk-based frontmatter
   slice and the yq-flavor capability probe, which the reference script does not carry
   because it assumes mikefarah yq.
2. **Migrate both spec bundles** from ungoverned `docs/specs/` into governed
   `knowledge/specs/`: `001-governance-parity` (archived, with its extraction record) and
   `002-phase-4-lifecycle-hardening` (draft, in flight).
   `docs/specs/` no longer exists.
3. **The exception is scoped to ADR-0013 only.** ADR-0012 stands for every other upstream
   convention, including the devbase image digest and any future template conventions.
   When a tagged `rka-template` release ships these rules, reconcile this ported script
   against the released one and record any divergence in `knowledge/progress.md`.

## Alternatives considered

1. **Wait for the tagged `rka-template` release (the standing ADR-0012 path).**
   Rejected by maintainer decision.
   It is the disciplined default and was this repo's recorded position for two days, but it
   leaves the repo's own motivating failure ungated for an unbounded period: the release
   train's timing is not under this project's control, and the gate's whole value is
   catching an un-retired spec at commit time.
2. **Adopt the conventions by hand without the validator rules** (move the bundles, keep
   rules 1-7).
   Rejected: the directory move without the gate is the weakest combination, taking on the
   new layout while leaving exactly the silent-rot failure mode unenforced.
   A convention nothing checks is the "status nothing advances" anti-pattern one level up.
3. **Vendor the whole reference validator verbatim.**
   Rejected: it would drop this repo's yq-flavor probe and awk frontmatter slice, which
   exist because the reference script assumes a mikefarah yq this environment does not
   always have. Porting the rules while keeping the local adaptations is the smaller,
   reversible change.

## Consequences

- The gate now bites in this repository: a fully-checked bundle left unarchived, a bundle
  with mixed statuses, or an archived document without an extraction record each fail
  `mise run lint`. All three were proven to fail by seeded violation before this ADR landed.
- Governed-document count rises from 12 to 18: the six bundle documents are now governed
  knowledge, validated on every commit, and carry the lifecycle.
- This repository is now ahead of its `rka-template` pin on one axis. That divergence is
  deliberate and recorded here; the reconciliation obligation at the next release is stated
  in the decision above so the divergence cannot become silent drift.
- ADR-0012 is not weakened. This is an exception with a named scope, a recorded rationale,
  and a defined end state, not a precedent for HEAD-tracking generally.
- Future feature specs in this repository are authored directly as governed bundles under
  `knowledge/specs/<NNN>-<slug>/`, with `<role>-<NNN>-<slug>` ids and a shared status.
