# ADR-0004 - Persistent SSH deploy key and scratch-branch local iteration for the Flux `GitRepository` source

Authored by brownfield discovery from decision evidence in
`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md` ("Decisions" item 4, lines
198-200) and `clusters/workload/README.md` ("Local iteration" section, lines 62-89).
No prior standalone document recorded this decision; it is extracted here because it
combines two related choices, each with discernible rejected alternatives and stated
consequences.

## Context

The `adr_status: accepted` is the native status, inferred:
`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md`
marks this "Decision closed" in Phase 2 status, line 107, and lists it under
"Decisions - Closed", item 4, lines 198-200 - inference, high confidence, stated twice
independently.

Flux's `GitRepository` needs a Git authentication mechanism to reconcile
`clusters/workload/` from this repository's GitHub remote (confirmed private via `gh
repo view`), and a mechanism to test uncommitted manifest changes against an ephemeral
local cluster without polluting `main`
(`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md` lines 198-200;
`clusters/workload/README.md` lines 62-89).

## Decision

Two related choices, both closed 2026-07-07:

1. **Authentication:** a persistent, one-time read-only SSH deploy key (generated via
   `gh repo deploy-key add`), not a key minted/revoked per cluster cycle.
   The private half is stored encrypted in the existing project SOPS secrets file
   (`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md` lines 198-199).
2. **Local iteration mechanism:** a scratch branch that the `GitRepository` is
   repointed to via `kubectl patch gitrepository/flux-system ... -p
   '{"spec":{"ref":{"branch":"<scratch-branch>"}}}'`, and repointed back to `main` once
   done (`clusters/workload/README.md` lines 64-77).
   The scratch branch lives on the same shared GitHub remote a real deployment's
   `GitRepository` would also point at, so it must be deleted from the remote when no
   longer needed - an abandoned scratch branch is a stale-but-harmless artifact there,
   not just local state (`clusters/workload/README.md` lines 80-82).

## Alternatives considered

1. **Per-cycle deploy key** (minted and revoked for each cluster lifecycle instead of
   persistent).
   Rejected in favor of a persistent key
   (`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md` line 198: "rather than one
   minted/revoked per cluster cycle").
   No further rationale is recorded beyond the stated preference; this is a thinner
   alternative than the local-iteration choice below (inference, low confidence, that
   operational simplicity was the driver, since it is not stated explicitly).
2. **An OCI-artifact push** as the local-iteration mechanism (pushing manifests to an
   OCI registry instead of a Git branch).
   Rejected: would change the Flux source *kind* (`OCIRepository` instead of
   `GitRepository`) for local iteration, breaking the property that the local-iteration
   mechanism itself never leaks into what a CAPI-provisioned cluster's Flux instance
   would need to consume (`clusters/workload/README.md` lines 83-86).
3. **Offline `flux build` diffing** (rendering and diffing manifests locally without
   ever pointing the live `GitRepository` at uncommitted content).
   Rejected for the same reason as the OCI-artifact alternative: the scratch-branch
   approach was chosen specifically because it "keeps the source *kind*
   (`GitRepository`) identical between local and cloud"
   (`clusters/workload/README.md` lines 83-86).

## Consequences

* Nothing currently detects or alerts if a local cluster is left pointed at a stale
  scratch branch; this is recorded as an accepted gap for a single-developer local dev
  tool, not a hardened multi-user workflow (`clusters/workload/README.md` lines 87-89).
* The persistent deploy key and the `sops-age` decryption key both live in the
  `flux-system` namespace, and that namespace's `NetworkPolicies` allow unrestricted
  egress (inherited unmodified from `flux install --export`'s stock output) with no
  egress scoping around the controllers that mount them - accepted for v1 alongside the
  YubiKey hardening deferral (`clusters/workload/README.md` lines 103-108).
* Verification of Phase 3 used this exact scratch-branch mechanism against the
  project's own feature branch, confirming it works as the intended day-2 development
  path, not just in theory
  (`docs/planning/PLAN-ephemeral-gitops-idp-2026-07-05.md` lines 121, 156).
